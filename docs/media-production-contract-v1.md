# PROMETHEUS V2 — MEDIA PRODUCTION CONTRACT V1

## Objective

Define the canonical audiovisual production model used by Prometheus V2.

The system does not treat a video as a single opaque file.

A production is a graph of:

RESEARCH
→ SCRIPT
→ SCENE_PLAN
→ VOICE
→ VISUALS
→ MUSIC
→ SFX
→ CAPTIONS
→ EDITING_BLUEPRINT
→ RENDER
→ AUDIO MASTER
→ QA
→ VIDEO_MASTER

Every material output is an artifact.

Every artifact is traceable to:

- run_id
- stage
- artifact_id
- object_key
- SHA-256
- contract version
- provider where applicable

## Core principle

The Editing Blueprint is the canonical source of temporal truth.

The renderer does not invent editorial decisions.

It receives:

1. assets
2. timing
3. transitions
4. captions
5. sound design
6. audio mix parameters
7. delivery profile

and renders exactly what the blueprint specifies.

## Audio

The final master is measured using EBU R128-compatible analysis.

Prometheus V2 uses a configurable loudness target, with the initial production profile targeting:

- Integrated loudness: -14 LUFS
- Maximum true peak: -1 dBTP
- LRA target: 11 LU

These are engineering defaults, not claims about platform algorithms.

Voice receives priority over music and SFX.

Music ducking and SFX levels are explicit blueprint parameters.

## Video

Canonical short-form delivery profile:

- 1080 × 1920
- vertical
- H.264
- AAC
- 48 kHz
- MP4
- default 30 fps

The profile is versioned and may evolve without changing the underlying contracts.

## Captions

Captions are not generated by the renderer.

The Caption Plan defines:

- text
- timing
- emphasis
- position
- animation

The renderer only executes the plan.

## QA

A VIDEO_MASTER cannot be considered production-ready unless:

- video stream exists
- audio stream exists
- container is valid
- duration is valid
- A/V duration difference is within tolerance
- required artifacts exist
- SHA-256 is available
- caption constraints pass
- audio master measurements pass
- artifact registry is coherent

## Determinism

Where possible, rendering must be deterministic.

The same:

- Editing Blueprint
- asset versions
- renderer version
- profile version

must produce reproducible output metadata.

The exact binary hash may differ if the encoder/runtime changes, therefore renderer version is part of the evidence.

## Separation of responsibilities

n8n:
- orchestration
- state transitions
- retries
- dependency management
- provider routing
- calling execution services

FFmpeg:
- media rendering
- compositing
- encoding
- audio processing
- loudness processing

PostgreSQL:
- control plane
- state
- contracts
- evidence
- registry

Storage Adapter:
- physical object storage

SeaweedFS:
- physical S3-compatible storage

No AI-Lab component may directly mutate Prometheus production state.
